# AS PAY — калькулятор рассрочки

Полностью рабочий, статический (HTML/CSS/JS, без сборки и зависимостей)
онлайн-калькулятор рассрочки для AS PAY — «Рассрочка по нормам Шариата».

## Запуск

Проект не требует сборки. Достаточно открыть `index.html` в браузере,
либо поднять любой статический сервер из корня папки:

```bash
# любой из вариантов
python3 -m http.server 8080
npx serve .
```

Затем открыть `http://localhost:8080`.

## Деплой

Это обычный статический сайт — файлы `index.html`, `css/`, `js/`, `assets/`.
Его можно сразу разместить на:

- GitHub Pages
- Netlify / Vercel (папка проекта как есть, build command не нужен)
- Любой хостинг, отдающий статические файлы

## Структура проекта

```
index.html          — разметка страницы и калькулятора
css/styles.css       — вся стилизация (дизайн-токены в :root)
js/app.js            — вся логика расчёта, валидации и UI
assets/logo.svg      — вордмарк AS PAY (placeholder, см. ниже)
assets/favicon.svg   — иконка вкладки
assets/pattern.svg   — геометрический тайл для фонового watermark
```

## Логотип

В диалоге не был прикреплён файл логотипа, поэтому в `assets/logo.svg`
создан аккуратный placeholder-вордмарк «AS PAY» в фирменной палитре
(тёмно-синий + золотой, геометрический знак — два наложенных квадрата,
образующих 8-угольную звезду). Чтобы подставить настоящий логотип —
просто замените файл `assets/logo.svg` (и при желании `assets/favicon.svg`)
на официальный, сохранив имена файлов: они уже подключены в `index.html`.

## Логика расчёта (кратко)

- Торговая наценка = `месяцы × 5%` от розничной цены товара.
- Взнос ≤ 40% от цены → стандартный расчёт: наценка считается от полной
  цены, взнос вычитается из итоговой стоимости, остаток делится на
  выбранное число месяцев.
- Взнос > 40% от цены → показывается блок «Индивидуальные условия»
  вместо стандартного предложения (форма заявки, без реальной интеграции
  с бэкендом — см. `js/app.js`, обработчик `leadSubmit`).
- Ежемесячный платёж округляется вверх до ближайших 100 ₽; последний
  платёж корректируется так, чтобы сумма всех платежей точно равнялась
  итоговому остатку. Для очень маленьких сумм, где такое округление
  невозможно, используется безопасное запасное распределение без
  округления до 100 ₽ и без отрицательных платежей (функция
  `buildSchedule` в `js/app.js`).
- Никаких сложных процентов, начисления на остаток долга или увеличения
  стоимости после оформления — процедура используется только один раз
  для определения фиксированной итоговой цены.

## Подключение реальной заявки на индивидуальный расчёт

Форма в модальном окне «Получить индивидуальный расчёт» сейчас работает
как UI-заглушка (показывает окно с подтверждением локально). Чтобы
отправлять заявки на реальный бэкенд/CRM/Telegram-бот, замените
содержимое обработчика `els.leadSubmit.addEventListener(...)` в
`js/app.js` на `fetch()`-запрос к вашему API.
